# 微信长文排版契约

> **本契约在 `wechat-article-writing` 调用 `gzh-design` 时作为不可选的上位约束传入**。
> 本契约高于所选主题的组件配方和默认智能处理；主题组件与本契约冲突时，省略该组件或
> 改用更简洁的兼容组件。
>
> 本契约由 `wechat-article-writing` 主 Skill 维护；`gzh-design`、`guizang-social-card-skill`
> 或任何主题组件必须按本契约实现，而非各自的默认行为。

## 文本级检查（最终正文确认前完成）

### T1. 段长与拆段
按自然阅读节奏拆段。目标视口是不宽于 390 CSS px、正文 14 或 15 px。
**单段不超过五六行**；超长段落按语义拆分。

### T2. 行末与孤立短行
不为凑版式插入生硬的手动换行。预判并减少**分行后仅剩两三个字的孤立短行**；
每段末行以约占正文可用宽度一半为目标。

### T3. 重点内容高亮
需要高亮的重点内容先确定为完整句子。高亮范围必须包含整句及其句末标点，
**禁止只高亮半句**；普通关键词下划线不算重点句高亮，但不得使用局部半高亮背景。

## 视觉级规则（HTML 排版必须满足）

### V1. 窄屏首屏
**窄屏首屏呈现一个完整阅读单元**，至少让读者读完一个完整的开头段落或引言；
不用色块、横线或装饰卡片切割首屏内容段。

### V2. 标题层级
正文一级章节标题（通常为 Markdown `##`）作为大标题，正文下级标题（通常为
`###` / `####`）作为小标题。**大标题与小标题使用明显不同的字体颜色**；
**大标题全篇使用同一格式和醒目颜色**，清楚标识新章节开始；小标题格式可按语义灵活，
但不得削弱层级区分。

### V3. 正文字号与字色
浅色背景主题的正文统一使用 **14 或 15 px 字号和 `#595757` 字色**。已登记的深色
常驻主题可改用其组件库"正文色"变量，但必须全篇统一，并与主题背景保持至少
**`4.5:1` 的对比度**；**不得为单篇文章临时另定正文色**。标题、链接和语义高亮可使用
各自的层级颜色，但不得改变普通正文的统一基线。

### V4. 行距与段间距
**行距与段间距保持舒适、疏密适度**；不得让相邻行或段落显得拥挤，也不得用过量
留白破坏连续阅读。

### V5. 装饰性横线
**默认移除装饰性横线和多余边框**。小标题确需短竖线等语义标记时只保留必要的一种，
不让线条成为视觉焦点。

## 复核与恢复

在窄屏预览和实际粘贴后的 DOM 中逐项复核上述 8 条规则（T1-T3 + V1-V5）。重点检查
**真实换行后的孤立短行、段落末行宽度和五六行上限**，而不是只检查 HTML 源码。

若只能通过改动正文文字才能修复，按 `references/recovery-rules.md` 从 `final`
阶段失效并重新完成审批及下游流程；**不得在已批准正文或已锁定预测之后静默改字**。

## 与 gzh-design 的契约

`gzh-design` 必须按本契约实现，而非主题默认：

- 接收本契约作为不可选的上位约束传入
- 主题组件与本契约冲突时，省略该组件或改用更简洁的兼容组件
- 输出 HTML 时已登记深色主题用其组件库"正文色"变量，否则使用 `#595757`
- 不为单篇文章临时另定正文色或字号

任何主题 / 子 Skill 若与本契约冲突，以本契约为准。
