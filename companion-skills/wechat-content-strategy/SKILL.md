# WeChat Content Strategy

把已确认选题和已核验证据转换为公众号长文大纲或资讯贴图大纲。

## 边界

1. 仅在选题角度已经确认，且 `research/evidence.md` 与
   `research/sources.json` 已存在时工作。
2. 只使用证据包、用户材料和已确认账号画像。不得自行搜索、补造或推断新事实，
   不得替代 Cheat 的选题评分和决策。
3. 根据已确认的内容形态只创建或更新一个策略产物：长文写 `outline.md`，资讯贴图
   写 `card-outline.md`。不得同时生成两种产物，不得撰写正文，不得修改
   `article-state.json`、账号画像、Cheat 状态或审批。
4. 外部事实锚点必须指向 `research/sources.json` 中能够支持该断言的来源；
   用户经历只能在 `research/evidence.md` 记录的表达范围内使用。
5. 证据不足时返回明确缺口并停止，不用常识或模型记忆填补。

## 工作流

### 1. 核查输入

读取已确认的选题、受众、文章目标、字数、账号 `voice.md` 和
`content-patterns.md`（如有），以及完整证据包。确认：

- 内容形态已明确为 `long-essay` 或 `news-card`。
- 选题角度和中心问题没有待确认项。
- 每条时效性或外部事实都有可追溯的 `supported_claim`。
- 用户材料与外部事实已明确分开。
- 不支持、冲突或只能作为观点的内容已经标记。

长文还必须在大纲前填写完整写前卡片：

- 真实摩擦
- 它揭示的机制
- 读者处境
- 一句核心判断
- 主要传播动作（点赞 / 转发 / 收藏，只选一项）
- 可转发立场
- 理性段落后的张力恢复点
- 标题承诺

写前卡片缺任一项时，列出缺口并把控制权交还 `wechat-article-writing`；不得继续
选择主增强策略或生成章节。

任一必要条件不满足时，列出缺口并把控制权交还
`wechat-article-writing`。

### 2. 选择输出分支

- `long-essay`：继续执行主增强策略、中心论点、文章参数和章节设计，最终只写
  `outline.md`。
- `news-card`：只生成 `card-outline.md` 后停止。五要素置顶，每张卡记录独立
  信息任务、文字上限、事实锚点和来源标记；不得进入长文章节设计。

资讯贴图的五要素必须全部由证据包支持：

- 发生了什么
- 为什么值得关注
- 账号一句判断
- 消息日期
- 可核查来源

### 3. 选择一个主增强策略

从以下策略中选择一个作为主策略，其他策略只能作为局部手段：

- 角度锐化：把宽泛主题收束为一个明确、可争辩的判断。
- 实操密度：围绕真实决策、动作、检查点和边界提高可执行性。
- 场景细节：用已提供的真实场景承载抽象观点。
- 决策对比：比较两个或多个有证据支持的选择及其适用条件。

记录选择理由，以及读者阅读后应发生的认知或行动变化。

### 4. 确定中心论点

用一句可检验、可由现有材料支撑的话表达中心论点。每个章节都必须推进该论点，
不得仅重复主题、堆砌背景或制造与证据无关的情绪。

### 5. 设置文章级写作参数

明确以下参数，但不得创建与账号声音冲突的新 persona：

- 开头方式
- 证据呈现
- 段落节奏
- 情绪强度
- 收尾形态

再生成本篇“文风执行卡”：

- 叙述位置
- 从 `voice.md` 和已验证规则中选择的 2–4 条稳定规则
- 本篇主动完成的 1–2 项文笔目标
- 从材料密度、说话位置、段落推进、中文词序和诚实不确定性中选择的 2–3 项活人感执行重点
- 无，或主动选择的 1 条待验证实验规则
- 无，或主动选择的 1 条终稿观察候选
- 最容易出现的 2–4 个禁用惯性
- 用户要求保留的表达；没有则写“无”
- 开头动作与收尾回收

账号 `voice.md` 与已验证规则优先于自动建议；这些参数和卡片只约束本篇执行。
不得把全部画像机械套入，不得用“更口语”“更有活人感”“像某某作者”替代可执行
动作，也不得把外部作者身份、口癖、粗口、固定标点、固定字数或固定结尾写入卡片。

文风执行卡完成后，交还总控调用必需的 `human-writing` 做活人感主执行；本 Skill
不直接采用外部 Skill 原文，不允许通用规则覆盖账号声音或新增素材。

### 6. 设计章节

每个章节记录：

- 信息任务
- 核心推进
- 证据锚点
- 与中心论点的关系
- 编辑锚点

章节职责必须互不重复。证据锚点使用来源标题、claim 标识或证据包中的稳定引用，
不得复制机器绝对路径。

设置 2–3 个编辑锚点，明确请求用户提供真实判断、经验、情绪或细节。不得替用户
填写；进入最终稿前必须解决或删除。

### 7. 写入事实边界

把材料分成：

- 可断言
- 仅可作为观点
- 不得写入

“未核实”标签不能把无证据内容变成可支持结论的事实。

### 8. 生成并自检策略产物

资讯贴图使用以下结构：

```markdown
# 资讯贴图大纲

## 五要素
- 发生了什么：
- 为什么值得关注：
- 账号一句判断：
- 消息日期：
- 可核查来源：

## 逐卡信息任务
### 卡片 1
- 信息任务：
- 文字上限：
- 事实锚点：
- 来源标记：
```

完成前检查：五要素齐全且可追溯，每张卡只有一个独立信息任务，没有长文段落、
未跟踪事实或虚构经历。完成后将 `card-outline.md` 交还总控并停止。

长文完成前检查：

- 写前卡片八项齐全。
- 恰好一个主增强策略和一个中心论点。
- 文风执行卡完整，稳定规则有明确来源，且没有外部作者 persona 或机械配额。
- 已为 `human-writing` 预留活人感主执行要求，且没有把它写成作者声音。
- 每节有独立职责并推进论点。
- 所有事实锚点均能回到证据包。
- 有 2–3 个真实用户编辑锚点。
- 没有正文段落、未跟踪事实或虚构经历。

将大纲交还总控，由总控负责状态记录和“大纲事实边界”确认。
